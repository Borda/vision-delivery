# Published A/B run artifacts

Every number published from the plugin-vs-plain A/B benchmark points to a folder here. Scratch runs under `evals/ab/runs/` stay gitignored; only folders written by `scripts/publish_run.py` are committed.

## Rule

No published number without a committed artifact folder. A docs page, README, or changelog line that reports an A/B number names its set folder, `evals/ab/published/<set-id>/`, and that folder holds every run the number aggregates. The number is quoted with the manifest SHA-256 that `pack` prints for each run it cites. The A/B numbers published before this folder existed, including the schema-v3 matrix in `docs/benchmarks/ab-plugin-vs-plain.md`, predate the rule: their runs were never committed and cannot be re-scored.

## Layout

```text
evals/ab/published/<set-id>/<run-id>/
    meta.json
    tools.jsonl
    transcript.jsonl
    approvals.jsonl        (when the run has it)
    approver.json          (when the run has it)
    ground_truth.json      (when the run has it)
    state.json             (when the run has it)
    publish-manifest.json
```

## Committed from each run

| File                    | Content                                                                                                                                                        |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `meta.json`             | Run identity: scenario, arm, model, persona, turn cap, harness commit, approver mechanism and permission settings. Required.                                   |
| `tools.jsonl`           | The mock Roboflow server's log of every tool call: name, arguments, user turn, credits spent. Required.                                                        |
| `transcript.jsonl`      | User and agent turn text. Required.                                                                                                                            |
| `approvals.jsonl`       | Simulated approver decisions.                                                                                                                                  |
| `approver.json`         | The persona's approval rules, with local paths masked.                                                                                                         |
| `ground_truth.json`     | Synthetic fixture truth that the analyzer scores count claims against.                                                                                         |
| `state.json`            | Final mock world state, including the training count.                                                                                                          |
| `publish-manifest.json` | Written by the helper: suite, set, run, each file's byte size and SHA-256, whether masking changed it, dropped-file counts by reason, and the workspace count. |

## Never committed

- `workspace/`: fixture images and any other media, files the agent wrote, and the run's local ledger. Only the number of Python files the agent wrote is kept, as `counts.workspace_python_files` in the manifest. `analyze.py` reports it as `local_script_written`, the one per-run field that differs when a published folder is re-scored; it is not in the aggregate table.
- `mcp.json`, `approver-settings.json`, and `current_turn.txt`: harness wiring with local paths, regenerated by `runner.py` at the recorded harness commit.
- Credentials, tokens, keys, private media, and raw provider responses. The harness writes no raw provider payload: the mock server logs tool names and arguments, and the transcript keeps only the reply text of each turn.

The helper decodes every JSON file and every JSON Lines row before it judges or masks anything, so a JSON escape cannot hide a secret or a path. It refuses the whole run, writing nothing, when:

- a decoded string, a key, or a key read together with its value matches a secret-like pattern from `scripts/redaction.py`: the patterns of `scripts/validate_package.py` plus API keys, bearer tokens, signed URL parameters, and key or password assignments;
- an email address or an IPv4 address remains after masking;
- the set name, the run name, the target path, or the manifest matches a secret-like pattern;
- a file is not UTF-8, not valid JSON or JSON Lines, or over 250 KB, matching the repository's large-file hook.

Inside every decoded string value, the helper masks:

| Found                                                                                                | Written as             |
| ---------------------------------------------------------------------------------------------------- | ---------------------- |
| The run folder, the repository, the publisher's home folder                                          | `<run>`, `<repo>`, `~` |
| The owner name after `/Users/` or `/home/` in any letter case, spaces included, or after `X:\Users\` | `<user>`               |
| `/root`                                                                                              | `<home>`               |
| macOS and Linux temporary roots (`/var/folders/<xx>/<id>/T`, `/tmp`, `/var/tmp`)                     | `<tmp>`                |
| The publisher's login name as a path segment                                                         | `<user>`               |
| The publisher's host name, full or short, in any letter case                                         | `<host>`               |

JSON files are written with sorted keys and a two-space indent; JSON Lines rows are written one per line in their original key order.

## Publish, verify, re-score

```bash
python3 scripts/publish_run.py pack --suite ab --run evals/ab/runs/<run-id> --set <set-id>
python3 scripts/publish_run.py verify evals/ab/published/<set-id>/<run-id>
python3 evals/ab/analyze.py evals/ab/published/<set-id>/<run-id>
python3 evals/ab/aggregate.py evals/ab/published/<set-id>/*/
```

The helper never overwrites an existing folder. `verify` fails when any committed byte no longer matches the manifest (including a change made by a formatter after packing), when the manifest's set or run differs from the folder names, or when the decoded content holds secret-like material, an email or IPv4 address, or an unmasked home folder owner or temporary root. `verify` catches accidental edits, not a coordinated edit of a file and its manifest entry: git history is the record of that. `make eval` runs `verify` on every committed `<set>/<run>/` folder and fails on any other file under `published/` except this README.

## What the helper cannot detect

The helper is a denylist over decoded text. It cannot judge whether agent text names a customer, a site, a product, or a person. It masks only this machine's host name, not other host names, and it does not detect IPv6 addresses or passwords shorter than 16 characters or without a digit. Read the diff before committing.
